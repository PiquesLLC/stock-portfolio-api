# Email Verification Smoke Runbook

## Purpose
Validate the full email verification path after enabling `EMAIL_VERIFICATION_ENABLED=true`:
- account starts unverified after signup
- guarded authenticated routes block unverified users
- OTP verification flips auth state immediately
- invalid/expired token paths return the expected auth errors

## Script
- Command: `npm run smoke:email`
- Script file: `scripts/smoke-email-verification.js`

## Prerequisites
- API server is running and reachable (default `http://localhost:3001`)
- `EMAIL_VERIFICATION_ENABLED=true` in the API environment under test
- A working `JWT_SECRET` in that environment
- For automatic OTP retrieval in non-production:
  - `NODE_ENV` is not `production`
  - `TEST_HELPER_KEY` is set on API
  - Smoke runner sends matching `SMOKE_TEST_HELPER_KEY` (or `TEST_HELPER_KEY`)
- For production runs (helper disabled):
  - set `SMOKE_VERIFY_CODE` from the OTP inbox manually
- If testing expired JWT behavior:
  - set `SMOKE_JWT_SECRET` to the API `JWT_SECRET` (script skips expired-token check if missing)

## Environment Variables
- `SMOKE_BASE_URL` (default: `http://localhost:3001`)
- `SMOKE_SIGNUP_EMAIL` (default: autogenerated `email-smoke-<ts>@example.com`)
- `SMOKE_SIGNUP_USERNAME` (default: autogenerated `email_smoke_<ts>`)
- `SMOKE_SIGNUP_PASSWORD` (default: `SmokePass123A`)
- `SMOKE_SIGNUP_DISPLAY_NAME` (default: `Email Smoke`)
- `SMOKE_TEST_HELPER_KEY` (or `TEST_HELPER_KEY`)
- `SMOKE_VERIFY_CODE` (manual OTP, mainly production)
- `SMOKE_JWT_SECRET` (optional, enables expired-access-token assertion)

## What The Smoke Test Verifies
1. `POST /auth/signup` returns `201` and `emailVerificationRequired=true`
2. `GET /auth/me` shows `emailVerified=false`
3. `GET /watchlists` returns `403` with `code=EMAIL_NOT_VERIFIED`
4. Invalid access token on guarded route returns `401 TOKEN_INVALID`
5. `POST /auth/resend-verification` responds (`200` or `429`)
6. Invalid OTP is rejected (`400`)
7. Valid OTP succeeds (`200`) on `POST /auth/verify-email`
8. `GET /auth/me` flips to `emailVerified=true`
9. Guarded route unlocks (`GET /watchlists` => `200`)
10. Invalid refresh token is rejected (`POST /auth/refresh` => `401 TOKEN_INVALID`)
11. Optional: expired access token returns `401 TOKEN_EXPIRED`
12. Cleanup: smoke account is deleted via `DELETE /auth/delete-account`

## Run Examples

### Local/dev with helper OTP capture
```bash
SMOKE_BASE_URL=http://localhost:3001 \
TEST_HELPER_KEY=dev-helper-key \
npm run smoke:email
```

### Production-style run (manual OTP)
```bash
SMOKE_BASE_URL=https://stock-portfolio-api-production.up.railway.app \
SMOKE_SIGNUP_EMAIL=your-real-inbox@example.com \
SMOKE_VERIFY_CODE=123456 \
npm run smoke:email
```

## Common Failure Modes

### `403` on `/auth/test/verification-code`
- Cause: missing/wrong helper key or helper disabled in production.
- Check:
  - API env has `TEST_HELPER_KEY` set.
  - Runner uses same value in `SMOKE_TEST_HELPER_KEY` or `TEST_HELPER_KEY`.
  - `NODE_ENV` is not `production` (helper route is disabled in production).
- Fix:
  - Correct key mismatch or use `SMOKE_VERIFY_CODE` instead.

### Signup blocked (`403 WAITLIST_NOT_APPROVED`)
- Cause: waitlist gate for the signup email.
- Check:
  - current waitlist settings in target environment.
- Fix:
  - use an approved email for smoke signup or run in an env with waitlist disabled for testing.

### Guarded route still blocked after OTP
- Symptom: `/watchlists` still returns `403 EMAIL_NOT_VERIFIED` after successful verify call.
- Checks:
  - `/auth/me` returns `emailVerified=true`.
  - `POST /auth/verify-email` returned `200`.
  - response set new auth cookies (token rotation on verify).
- Fix:
  - rerun smoke with a fresh account; investigate token cookie propagation if issue persists.

### Invalid OTP step unexpectedly passes
- Cause: very low-probability accidental code match.
- Fix:
  - rerun smoke; script uses a code different from the captured OTP, but random collision is theoretically possible.

### Cleanup fails
- Cause: auth cookies invalidated or password mismatch.
- Impact: smoke user may remain in DB.
- Fix:
  - delete the test user manually by username/email from Prisma Studio or rerun with unique identity.

## Rollback Steps (If Verification Blocks Legitimate Traffic)
1. Set `EMAIL_VERIFICATION_ENABLED=false` in the target environment.
2. Redeploy API.
3. Re-run a minimal auth smoke:
   - `GET /auth/me` with an existing session works.
   - guarded routes no longer return `EMAIL_NOT_VERIFIED`.
4. Keep OTP email sending intact while gate is off to preserve observability.
5. Triage root cause, patch, then re-enable with `EMAIL_VERIFICATION_ENABLED=true`.
